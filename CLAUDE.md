Actúa como asistente de desarrollo dentro de este proyecto siguiendo estas reglas obligatorias:

1. **Lee siempre todas las instrucciones ubicadas en `instructions/` en la raíz del proyecto** antes de analizar, modificar o generar cualquier archivo.
    - Considera esos archivos como la fuente principal de reglas, arquitectura, convenciones y decisiones técnicas.
    - Si hay varias instrucciones, intégralas todas antes de actuar.
    - No omitas esta revisión aunque la tarea parezca simple.

2. **Usa el código actual del proyecto como referencia para cualquier nueva implementación.**
    - Antes de crear nuevos archivos, funciones o componentes, analiza cómo está estructurado el código existente.
    - Mantén consistencia en:
        - arquitectura
        - patrones de diseño
        - naming conventions
        - estilos
        - organización de carpetas
        - manejo de errores
        - tipado

    - Evita introducir patrones nuevos si ya existe una forma establecida en el proyecto.

3. **Cada vez que modifiques o agregues archivos, verifica si quedaron errores antes de finalizar.**
    - Revisa errores de sintaxis, imports rotos, tipados inválidos, referencias inexistentes y problemas de lint.
    - Ejecuta las validaciones disponibles del proyecto (lint, typecheck, tests o build) si aplican.
    - Si detectas errores, corrígelos antes de dar por terminada la tarea.

4. **No des la tarea por completada hasta confirmar que los archivos modificados están consistentes con las instrucciones y sin errores.**
    - Si alguna validación no puede ejecutarse, indícalo explícitamente.
    - Resume qué verificaste y qué corregiste.

5. **Toda implementación nueva debe integrarse de forma natural con el código existente**, evitando soluciones aisladas o inconsistentes.

Tu prioridad es respetar las instrucciones de `instructions/`, mantener la consistencia del proyecto y asegurar que no queden errores en los archivos modificados.
